# Как работает подбор

В `web/recommender.js` находится независимая от интерфейса модель: `evaluate()`
оценивает одну игру, `rank()` сортирует коллекцию по убыванию суммы баллов.
Одинаковая модель используется локальным каталогом и сборкой GitHub Pages.

## Единственное исключение из подборки

Игра исключается только при известном `max_players`, если участников больше этого
максимума. Равенство допустимо. Вес состава компании можно обнулить, но проверка
максимума продолжает работать.

Если участников меньше `min_players`, игра остаётся с меньшим баллом за состав
компании и предупреждением. Неизвестный максимум не исключает игру; интерфейс
предлагает уточнить его перед партией.

## Баллы и веса

Для выбранного пожелания рассчитывается соответствие от 0 до 1. Оно умножается
на вес критерия. Баллы всех выбранных критериев складываются:

`баллы = Σ (вес × соответствие)`

`процент = round(100 × баллы / Σ весов выбранных критериев)`

Без пожеланий процент не показывается. Отключённые критерии и критерии с нулевым
весом не входят ни в числитель, ни в знаменатель. Ноль не отменяет проверку
максимума игроков. Все веса доступны в разделе «Что для вас важнее?» (0–50).

| Критерий | Обычный вес |
| --- | ---: |
| Поисковый запрос | 30 |
| Жанр | 24 |
| Формат | 22 |
| Состав компании | 20 |
| Время партии | 14 |
| Сложность игры | 12 |
| Сложность правил | 10 |
| Впечатление | 10 |
| Объяснение правил | 8 |
| Механика | 8 |
| Наличие | 6 |
| Избранное | 6 |

Жанры и механики допускают множественный выбор. Соответствие каждого критерия —
число совпавших выбранных значений, делённое на число выбранных значений.
Например, 2 из 3 жанров дают 2/3 веса жанров. Общее число выбранных значений
не увеличивает вес критерия. Пустой список отключает критерий, повторы не учитываются.
В интерфейсе доступны поиск по спискам, флажки, отдельные метки выбранного,
снятие одной метки и очистка всего списка. Это влияет только на баллы.

Впечатление, наличие и избранное дают полное совпадение или ноль.
Формат «Каждый за себя» включает дуэль; пожелание «Дуэль» совпадает
с дуэльным форматом, определённым по данным кооперации и числу игроков.

Время партии и правил получает полный балл, если укладывается в пожелание.
За превышение балл постепенно уменьшается: `желаемое время / время игры`.
Сложность: `1 − abs(сложность игры − желаемая) / 8` на шкале 1–9.
Сложность правил — отдельное поле `rules_difficulty`, шкала 1–5. Если правила
не сложнее желаемых, даётся полный балл; иначе:
`1 − max(0, сложность правил − желаемая) / 4`.
Время на объяснение берётся отдельно из `time_for_rules_min` и не подменяет сложность.

За состав компании: 1 внутри рекомендованного диапазона (либо допустимого,
если рекомендации не указаны), 0,75 вне рекомендованного, но внутри допустимого.
При нехватке игроков: `max(0, 0,3 − 0,1 × число недостающих игроков)`.

Поиск даёт 1 за фразу в названии, 0,8 за фразу в описании/тегах,
до 0,6 за отдельные слова. Регистр и различие е/ё не учитываются.
Поиск, наличие и избранное тоже являются предпочтениями: они повышают подходящие
игры, сохраняя остальные среди доступных альтернатив.

Неизвестное значение получает 0 баллов с объяснением «неизвестно» или
«в базе не указано»; выбранный вес остаётся в знаменателе. Неизвестное значение
не изображается как совпадение и не исключает игру.

## Что показывает интерфейс

При выбранных пожеланиях сначала видны шесть лучших игр. Первая дополнительно
выделена; остальные доступны по кнопке «Ещё варианты». При нулевых баллах у всех
игр интерфейс сообщает, что точных совпадений нет. В карточке есть положительные
причины и несовпадение/предупреждение; полный расчёт виден в подробностях.
«Помочь выбрать» выбирает из трёх лидеров. Без пожеланий показан обычный каталог.
Другие способы сортировки действуют явно по выбору пользователя.

Пресеты заполняют видимые поля и сбрасывают веса к обычным значениям.
Скрытых ограничений у пресетов нет. Ручная правка полей снимает выделение пресета.

## Источники характеристик

`fetch_games()` в `app.py` читает `games` и добавляет массивы `genres` и
`mechanics` через связи `game_genres → genres` и `game_mechanics → mechanics`.
Запросы выполняются по ID, без зависимости от названия игры. Для старой схемы
поддерживаются текстовые `games.genre` и `games.mechanics` с разделителем `;`.
Ошибка чтения существующей связи приводит к явному резервному режиму,
а не к выдаче неполных данных под видом подключённой базы.

Жанры и механики в списках выбора поступают из этих массивов. Впечатления —
непосредственно из `impression`, с разделением по `;`. Новые значения появляются
после загрузки каталога автоматически. Индивидуальной разметки по названиям нет.

Формат обобщается из `level_of_cooperation`: сначала полукооперация, затем
командное соревнование, полная кооперация, соревнование. Для дуэли нужны явное
описание соревнования двух игроков или соревновательный формат с диапазоном 2–2.
Неизвестный текст кооперации не подменяется выдуманным форматом; исходный текст
показывается в подробностях. Жанры и формат являются отдельными критериями.

`rules_difficulty`, `complexity_of_game` и `time_for_rules_min` поступают из своих
числовых полей. Пустые поля остаются неизвестными и не исключают игру.
В текущей базе 72 игры, у 60 заполнены связи жанров/механик и сложность правил;
оставшиеся 12 продолжают участвовать с неизвестными значениями этих полей.

`python -B export_catalogue.py` обновляет `data/catalogue.json` из MySQL, включая
связанные таблицы; выполняются только SELECT/SHOW. Скрипт не меняет базу и
останавливается при пустом результате. `python -B build_public.py` использует
этот снимок для GitHub Pages. После изменения данных экспорт и сборку нужно повторить.

## Проверки

`python -B -m unittest test_app.py` — валидация и резервный каталог.

`python -B qa_recommendations.py` (либо `qa_browser.py`) — контрольная сумма
баллов, смена лидера при изменении весов, отсутствие других исключений,
неизвестные значения, множественные жанры/механики, пустые списки, доли совпадений,
снятие меток, поиск по спискам, жанры/форматы/впечатления/механики из базы, пресеты, поиск, избранное,
клавиатура, детали, мобильная вёрстка и публичная сборка из подпапки.
Нужны Playwright и установленный Chrome. Проверка использует снимок каталога,
не подключается к MySQL и не меняет записи. Скриншоты сохраняются в `artifacts/`.
